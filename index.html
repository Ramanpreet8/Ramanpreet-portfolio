MLH Hack Day

Live Interactive Educational Game

A real-time multiplayer quiz platform built in under 7 hours at MLH Hack Day @ CityTech, featuring server-authoritative Socket.IO room management, instant QR-code player onboarding, and dynamic score leaderboards.

Architecture & Engineering Decisions: Centralized all game-state transitions in a server-authoritative Socket.IO state machine with end-to-end TypeScript contracts shared between client and server. By disallowing client-side timer manipulation and attaching monotonic sequence numbers to WebSocket events, the architecture prevented client score tampering and kept countdowns and live leaderboards synchronized across devices. Integrated Google Gemini API for dynamic trivia generation tailored to player-selected topics.

Problem

Classroom and hackathon trivia tools often demand cumbersome account creation or suffer from noticeable state lag between host projector displays and mobile player phones. The challenge was building and shipping a lag-free, instant-join multiplayer game within an intense 7-hour hackathon window.

My Role & Architecture

Co-built the application in a team of 2 during a 7-hour hackathon. I focused on backend systems: built the Node.js/Express server, configured Socket.IO room lifecycle orchestration, defined shared TypeScript data contracts, and integrated the Google Gemini API for question generation.

Hard Bug & Tradeoff

Tradeoff: Disallowed clients from running local timers or calculating score increments to prevent race conditions and tampering; centralized all transitions in a server-authoritative tick state machine (Lobby → Question → Reveal → Leaderboard → Podium). Hard Bug: Rapid phase shifts caused out-of-order WebSocket packet delivery on mobile browsers. Fixed by attaching monotonic state sequence numbers and broadcasting synchronized server timestamps so countdowns stayed consistent across client devices.

Result

Engineered a server-authoritative Socket.IO state machine with shared TypeScript contracts to govern room lifecycles and centralize state transitions on the backend, preventing client-side score manipulation and maintaining synchronized gameplay across concurrent mobile players joining via dynamic QR codes and PINs during the live MLH Hack Day demonstration.

What I'd Do Differently

Add a Redis pub/sub adapter to scale the Socket.IO server horizontally across multiple instances, and cache generated trivia in a KV store to eliminate LLM generation latency during high traffic.

Seaborn Analysis: Pediatric vs. Adult Asthma ED Visit Disparity Across NYC Boroughs (NYC Open Data)
Data Analysis

Air Pollution & Public Health Data Analysis

An environmental data analysis pipeline investigating whether fine particulate air pollution (PM2.5) directly correlates with pediatric asthma emergency room visits across New York City neighborhoods.

Analytical Thinking & Validation: Reconciled 19,827 air-quality and 48 health records in Python, caught and resolved a dataset double-counting error that doubled visit counts, and expanded from an underpowered 5-borough test to a 42-neighborhood sample (n = 168) to obtain statistically defensible findings.
Read Case Study ▼

Problem

Public discourse frequently assumes fine particulate matter (PM2.5) has a direct, one-to-one correlation with acute pediatric asthma hospitalizations across NYC. However, combining disparate open municipal records without validating temporal collection methods risks false statistical conclusions.

My Role & Architecture

Sole data analyst and visualization engineer. Extracted, cleaned, and reconciled municipal datasets from NYC Open Data and the NYC Environment & Health Data Portal using Python, Pandas, NumPy, SciPy, Seaborn, and Plotly in JupyterLab.

Hard Bug & Tradeoff

Bug: The asthma dataset reports both borough and neighborhood rows for the same visits, and my grouping summed both, doubling every count. I fixed the filter and added a check that borough totals match the citywide row.

Analytical trap: A 5-borough correlation looked strong (r = 0.78) but wasn't significant (p = 0.12). Moving to 42 neighborhoods across matched time periods gave a weaker, more honest result (r = 0.28, p < 0.001). I also documented that "visits due to PM2.5" are Health Department estimates partly calculated from PM2.5 itself, so some correlation is built in.

Result

Delivered three reproducible notebooks analyzing 19,827 air-quality and 48 health records across 42 neighborhoods (n = 168). Verified key findings: Bronx pediatric asthma ED rates were 3.8× Staten Island's, and PM2.5 levels dropped ~40% between 2009 and 2024.

What I'd Do Differently

Repeat the analysis with total observed asthma ED visits (not derived from PM2.5), and add Census income and housing data in a multivariable regression to separate pollution from socioeconomic factors.
