Gameplay Walkthrough: Topic Selection, Host Lobby, Instant QR Join, Authoritative Timer, & Leaderboards

Problem

Classroom and hackathon trivia tools often demand cumbersome account creation or suffer from noticeable state lag between host projector displays and mobile player phones. The challenge was building and shipping a lag-free, instant-join multiplayer game within an intense 7-hour hackathon window.

Architecture & Decisions

Centralized all game-state transitions in a server-authoritative Socket.IO state machine with end-to-end TypeScript contracts shared between client and server. By disallowing client-side timer manipulation and attaching monotonic sequence numbers to WebSocket events, countdowns and live leaderboards stayed synchronized across devices.

Hard Bug & Tradeoff

Tradeoff: Disallowed clients from running local timers or calculating score increments to prevent race conditions; centralized all transitions in a server-authoritative tick state machine (Lobby → Question → Reveal → Leaderboard → Podium). Hard Bug: Rapid phase shifts caused out-of-order WebSocket packet delivery on mobile browsers. Fixed by attaching monotonic state sequence numbers and broadcasting synchronized server timestamps so countdowns stayed consistent across client devices.

Result

Engineered a server-authoritative Socket.IO state machine with shared TypeScript contracts to govern room lifecycles and centralize state transitions on the backend, maintaining synchronized gameplay across concurrent mobile players joining via dynamic QR codes and PINs during the live MLH Hack Day demonstration.

What I'd Do Differently

Add a Redis pub/sub adapter to scale the Socket.IO server horizontally across multiple instances, and cache generated trivia in a KV store to eliminate LLM generation latency during high traffic.

mealRouter.post("/meal", passport.authenticate("jwt", { session: false }), async (req, res) => {
  if (req.user?.email === "demo@nutribloom.com") {

Air Pollution & Public Health Data Analysis

An environmental data analysis pipeline investigating whether fine particulate air pollution (PM2.5) directly correlates with pediatric asthma emergency room visits across New York City neighborhoods.

My Role: Sole Data Analyst & Visualization Engineer — extracted, cleaned, and reconciled municipal datasets using Python, Pandas, NumPy, SciPy, Seaborn, and Plotly in JupyterLab.

Python Pandas NumPy SciPy Seaborn Plotly JupyterLab
GitHub
Read Case Study ▼
Seaborn Analysis: Scatter plot of PM2.5 vs. asthma ED rates across 42 NYC neighborhoods (NYC Open Data)

Problem

Public discourse frequently assumes fine particulate matter (PM2.5) has a direct, one-to-one correlation with acute pediatric asthma hospitalizations across NYC. However, combining disparate open municipal records without validating temporal collection methods risks false statistical conclusions.

Analytical Thinking & Validation

Reconciled 19,827 air-quality and 48 health records in Python, caught and resolved a dataset double-counting error that doubled visit counts, and expanded from an underpowered 5-borough test to a 42-neighborhood sample (n = 168) to obtain statistically defensible findings.

Hard Bug & Tradeoff

Bug: The asthma dataset reports both borough and neighborhood rows for the same visits, and my grouping summed both, doubling every count. I fixed the filter and added a check that borough totals match the citywide row.

Analytical trap: A 5-borough correlation looked strong (r = 0.78) but wasn't significant (p = 0.12). Moving to 42 neighborhoods across matched time periods gave a weaker, more honest result (r = 0.28, p < 0.001). I also documented that "visits due to PM2.5" are Health Department estimates partly calculated from PM2.5 itself, so some correlation is built in.

Result

Delivered three reproducible notebooks analyzing 19,827 air-quality and 48 health records across 42 neighborhoods (n = 168). Verified key findings: Bronx pediatric asthma ED rates were 3.8× Staten Island's, and PM2.5 levels dropped ~40% between 2009 and 2024.

What I'd Do Differently

Repeat the analysis with total observed asthma ED visits (not derived from PM2.5), and add Census income and housing data in a multivariable regression to separate pollution from socioeconomic factors.
